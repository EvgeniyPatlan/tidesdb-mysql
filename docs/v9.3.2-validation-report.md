# TidesDB v9.3.2 engine bump — validation report (release v0.3.1)

Validation of bumping the bundled storage engine from **TidesDB v9.3.0** to
**v9.3.2** (two upstream patch releases). The engine continues to ship
**unpatched**, and no plugin code changes were required: v9.3.1 and v9.3.2 are
patch-level and introduce no new public enums or error codes for the handler's
`tdb_rc_to_ha` to map. See [CHANGELOG.md](../CHANGELOG.md) and
[KNOWN-ISSUES.md](../KNOWN-ISSUES.md).

## What v9.3.1 + v9.3.2 add (inherited by the plugin, no code changes)

- **Concurrency / memory-safety hardening (v9.3.1).** Five distinct fixes:
  clock-cache reader-pin wraparound at 128 concurrent readers (would corrupt
  zero-copy buffers under load); flush-cleanup use-after-free when more than
  sixteen immutable memtables accumulated in a single pass; dangling pointer
  left by transaction reset on repeatable-read / snapshot; duplicate
  column-family registration race; 32-bit MSVC atomic fallbacks.
- **Reader FD starvation fixed (v9.3.1).** Engine-side counterpart to the
  fd-pressure behaviour we documented in the v0.3.0 100 GiB stress run.
  A flush-path descriptor-accounting leak (a bare `close` skipping the
  counted-open decrement) is fixed, and reader/reaper budgets are unified so
  the reserve always stays available.
- **Backpressure simplified (v9.3.1).** The L1 file-count hard stop is removed
  (it blocked writes on a compaction-paced signal that normally settles on its
  own). Write admission is now governed by the L0 queue stall plus the
  active-memtable ceiling; L1 contributes only graduated delays.
- **Parallel compaction within a round (v9.3.1).** Per-CF rounds borrow
  ephemeral helper threads with work-stealing (the calling thread participates)
  and shard merge output into key-range subcompactions. Validated under
  sanitizers; ~25 % higher ingest throughput in upstream's tests with clean
  mid-round-kill recovery.
- **Large bloom filters / block indexes (v9.3.2).** Auxiliary klog blocks
  exceeding the 4 GB block-manager size are now chunked. **Backwards-compatible**.
- **`_tidesdb_cancel_background_work_` (v9.3.2).** Quick-shutdown helper for
  large flush / compaction queues.

`./mtr --suite=tidesdb --force --max-test-fail=0` on `tidesdb/mysql-mtr:9.7`:

```

2 tests were skipped, 2 by the test itself.
```

**PASS.** Same 61/61 result as v0.3.0. Includes `tidesdb_stress`,
`tidesdb_write_pressure`, `tidesdb_ttl`, `tidesdb_single_delete`, and the
security/spatial/vcol suites.

## Test 2 — mwbench engine-integrity gate

`bench/mwbench/run-mwbench.sh` (8 GiB target, 1 KiB values, 4 writers / 4
readers, 64 MiB write buffer, 512 MiB block cache). Heavy sequential ingest +
concurrent byte-verified readers through a delete → compaction reclaim cycle.
PASS iff `point_misses == seek_misses == range_misses == mismatches == 0`.

```
rows=48  keys=8260352  peak_ssts=86  disk=8135863873
point_misses=0  seek_misses=0  range_misses=0  mismatches=0
verdict: PASS -- no lost writes, no corrupted values across the run
```

**PASS.** Deletes enabled, full tombstone + compaction coverage. The carried
mwbench harness patch (`docker/patches/mwbench/0001-publish-delete-predicate-before-loop.patch`)
applied cleanly against the pinned mwbench commit `d214ed83`.

**PASS.** mysqld restarted without manual repair; post-restart `d_next_o_id`
≥ pre-kill watermark for every district, orders rows match `d_next_o_id - 1`.

## Verdict

**PASS.** All four gates green. The bump to TidesDB v9.3.2 shows no functional
regression, no data loss or corruption under stress, durable crash recovery,
and equivalent throughput on the WARE=100 profile — with the upstream
concurrency-safety, fd-starvation, backpressure, and parallel-compaction
improvements inherited for free. Cleared to ship as **v0.3.1**.
